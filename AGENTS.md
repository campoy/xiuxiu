# Working in this repo

Personal iOS voice journal: record, stop, transcribe on-device with whisper.cpp, copy out
punctuated text. One SwiftUI target, no third-party dependency except whisper.cpp.

**Read `PLAN.md` first.** It is the live handoff document between sessions and says what is
done, what is next, and which decisions are already settled.

## Keep PLAN.md current

PLAN.md is not a historical record. When a change makes something in it wrong, fix it in the
same change: tick the boxes that are now done, correct statements that are no longer true, and
write down findings the next session would otherwise have to rediscover.

One exception: anything in the "Decisions (already made, don't relitigate)" table that hinges on
a decision the user has not made yet should be raised with them, not silently edited.

## Build

```sh
xcodegen        # regenerate xiuxiu.xcodeproj after editing project.yml
xcodebuild -project xiuxiu.xcodeproj -scheme xiuxiu \
  -destination 'generic/platform=iOS Simulator' build
```

`xiuxiu.xcodeproj` and `xiuxiu/Info.plist` are both generated by XcodeGen. Never edit them by
hand and never commit them. Change `project.yml` and re-run `xcodegen`.

## whisper.cpp is vendored on purpose

`Packages/WhisperFramework/whisper.xcframework` is the prebuilt v1.9.2 XCFramework, committed
(195 MB) so that a clone builds with no network access.

Do not "fix" this back into a remote `binaryTarget` with a URL and checksum. Resolving a remote
binary artifact makes SwiftPM look up github.com credentials in the keychain, which blocks on an
authorization dialog and can deadlock the build with no useful error.

To upgrade: build an XCFramework with whisper.cpp's `./build-xcframework.sh` and replace the
directory. Releases v1.9.3 and later ship no prebuilt XCFramework zip.

## Simulator

- **The simulator needs the CPU backend.** Its Metal driver ships buffers to the host GPU over
  XPC, and the model's 573 MB buffer trips an XPC shared-memory limit, trapping inside
  `MTLSimDevice newBufferWithLength:`. `Whisper.init` already handles this with
  `#if targetEnvironment(simulator)`. A device has unified memory and uses Metal normally.
- Only the iOS 17.0 runtime is installed, which happens to match the deployment target.
- Stage the model rather than letting the app download 547 MB:

  ```sh
  SIM=<device-udid>
  xcrun simctl install $SIM "$(ls -d ~/Library/Developer/Xcode/DerivedData/xiuxiu-*/Build/Products/Debug-iphonesimulator/xiuxiu.app)"
  cp ggml-large-v3-turbo-q5_0.bin \
     "$(xcrun simctl get_app_container $SIM cat.campoy.xiuxiu data)/Documents/"
  ```

  The model is `ggml-large-v3-turbo-q5_0.bin` from
  `https://huggingface.co/ggerganov/whisper.cpp/resolve/main/`, 574,041,195 bytes.
- whisper.cpp logs to stderr, so `xcrun simctl launch --console-pty $SIM cat.campoy.xiuxiu` is
  the fastest way to see whether the model actually loaded. Expect about 4 seconds on CPU.
- If a crash leaves no useful output, the report is in `~/Library/Logs/DiagnosticReports/`; its
  faulting-thread frames are usually enough to identify the cause.

## What cannot be automated here

Recording needs a human. There is no tap automation available, and the simulator records from
the Mac's microphone, so there is nothing to inject. Anything that exercises
record → transcribe → Copy has to be driven by hand.

Transcription itself can be tested without a microphone by handing a 16 kHz mono WAV straight to
`Whisper.transcribe(fileAt:)`, which is the same entry point `AppModel` uses.

## Style

Match the surrounding code. Single target, no abstraction layers, no settings screens, no
patterns introduced for their own sake. Comments explain why something is the way it is, not
what the line does. `xiuxiu/Config.swift` holds the tunable knobs (language, initial prompt,
model URL).
